# MemoDeck · 核心业务能力说明（给界面/体验设计用）

版本对应：应用 2.2.0，题库格式 viewVersion 1.0.0。以下内容全部来自代码与既有规范，不是设想。

## 1. 项目目标

一句话：**把"题"和"程序"彻底分开的离线背题工具**——程序不认识任何学科，只认识一份 JSON；换一份 JSON 就变成那个科目的刷题应用。

| 目标 | 含义 | 对设计的意味 |
|---|---|---|
| 零门槛可用 | 双击本地文件就能用，不装环境、不联网、不起服务 | 首屏不能假设网络、不能假设登录、不能加载外部资源 |
| 背题效率优先 | 把时间花在真正记不住的题上：低频打扰、高频巩固 | "今天该学什么"是第一等问题，比"我学了多久"重要 |
| 考完立刻知道错在哪 | 客观题答错当场给标准答案与解析，答对即前进 | 判分反馈的即时性比分数呈现更重要 |
| 薄弱项自动收敛 | 错题只进一次、只会在被真正掌握后离开 | 错题量应该随使用下降，不是随使用膨胀 |
| 数据可迁移、可自主 | 题库与学习数据都是可读的 JSON，可导出可导入 | 一切数据必须能被用户看见并接管 |
| 单设备自用，不做账号 | 无登录、无后端、无同步，数据只在本机浏览器 | **不要设计任何协作、多端、账号相关界面** |

从实现与文档归纳出的优先级（用户未书面确认）：P0 导入题库→每日该学什么→练→错题收敛的闭环；P1 计时自测；P2 数据备份与迁移；P3 分发便利（本地文件 / 静态托管 / 可安装到桌面）。

真实使用数据参考：用户实际跑的是**企业安全生产题库（约 110 题，含多选）**，仓库内置的 13 题历史示例只是兜底。设计不要按"十几道题"的规模来定，要能撑到**千题级、多卷、长选项文本**。

## 2. 核心概念（数据事实）

| 概念 | 事实 |
|---|---|
| 题库（bank） | 一份 JSON。含元信息、功能开关、若干"卷"。 |
| 卷（paper） | 题库内的一组题。一份题库可含多卷。同一时间只有一个"当前卷"生效。 |
| 题（question） | 最小业务单位。有唯一卷内 id、题型、题干、标准答案、可选解析。 |
| 题目全局标识 gid | `卷id::题id`。**学习进度、错题判重、会话恢复共用这一个键**；不同卷里 id 相同的题是不同题目。跨导入、跨会话稳定。 |
| 题库标识 | 用 `meta.title`（不是 id）。换题库后旧的未完成会话不会出现；**标题改名会让恢复点失效**。旧格式题库可能没有 title。 |
| 题型 | 6 种，注册表驱动，可扩展。 |
| 客观题 | 3 种：判断、单选、多选。系统自动判分。 |
| 主观题 | 3 种：填空、专项题、问答（+ 所有未知题型）。**系统不判分，由用户对照参考答案自评**。 |
| 学习进度 | 按 gid 记录跨会话状态：new / learning / review / mastered，含作答次数、连对次数、下次复习时间。 |
| 错题本 | 全局一份（不分题库），按 gid 判重，同一题只留一条。含出错次数、连对次数、状态、出错来源。 |
| 出错来源 | 5 种：学习 / 练习 / 记忆闯关 / 摸底速览 / 考试。 |
| 恢复点 | 按模式分桶（学习 / 练习 / 考试各一个，互不覆盖）。考试桶额外保存**逐题作答快照**。 |
| 每日任务 | 由调度器回答"今天应该学什么"，产出一个题目队列。 |

## 3. 题型与作答契约

| 题型 | 标识 | 答案形状 | 判分 |
|---|---|---|---|
| 填空题 | `fill_blank` | 若干"空"，每空一个标准答案 | 用户自评 |
| 判断题 | `true_false` | 布尔 | 系统判分 |
| 单选题 | `single_choice` | 选项集合 + 单个选项键 | 系统判分 |
| 多选题 | `multi_choice` | 选项集合 + 选项键数组 | 系统判分 |
| 问答题 | `essay` | 一段参考文本 | 用户自评 |
| 专项题 | `special_fill_blank` | 同填空题 | 用户自评 |

- 选项键固定为大写字母，题干与选项文本是**纯文本**（当前格式不支持图片、公式、富文本、音频）。
- 填空题干里空位写作 `____`，与答案列表按顺序对应，不严格校验对齐。
- 多空答案在"一道题一次输入"的口径下靠 `|` 或 `｜` 分隔；**这个分隔符目前不参与任何判分**，只是给用户的手动约定，以及在"手动加题"时用来拆分成逐空答案。
- **没有逐空判分、没有文本比对**（忽略大小写/同义词/空白等都不存在）。设计主观题时不要假设有自动批改。
- 未知题型不会报错：照常显示题干，把答案字段原样当答案展示。
- 展示语义要求：凡带选项的题，**选项文本必须与答案一起可见**（背诵场景需要"题干+选项+答案"同屏读到），不能只显示答案字母。

### 判分规则（全局唯一口径）

| 题型 | 判对条件 | 未作答 |
|---|---|---|
| 判断 | 所选与标准布尔一致 | **判错**（不送分） |
| 单选 | 所选字母与标准全等 | **判错** |
| 多选 | 所选字母集合**排序后全等** | **判错** |

- **多选题没有部分给分**：漏选、多选、错选都算整题错。
- 答案形状不合约定（如多选写成字符串）时按空集处理，该题永远判错，但不会崩。
- **判分 ≠ 掌握**：判分只产出当次对错；"掌没掌握"由跨会话进度独立维护。这是两个不同的数，界面上必须能区分（见 §5、§11）。

## 4. 功能清单（能力，不含形态）

### 4.1 数据接入

- 题库获取渠道：远程 URL 拉取 / 粘贴 JSON 文本 / 选择本地文件 / 拖入文件 / 内置兜底题库。
- 加载优先级：本机缓存 → 配置的远程地址 → 内置兜底。缓存里的数据损坏时自动清除并回退。
- 三种输入形态自动归一化：标准格式、顶层数组、旧版"卷子键+分题型对象"格式。
- 当前来源与读取时间必须可辨识（远程 / 粘贴 / 文件 / 缓存 / 内置是五种不同事实，其中"缓存"可能来自任意前四种）。
- 刷新：来源是远程时可重新拉取；否则明确告知无可刷新地址。
- 多卷：可切换当前卷。**卷级筛选只存在于数据接入这一层，各功能入口内不重复提供**（见 §11）。
- 题库导出：下载当前题库 JSON / 复制到剪贴板。
- 手动加题：可当场录入一道题（题干+题型+选项+答案），加入当前卷；无当前卷时新建一卷。
- AI 辅助：复制一段现成提示词（配套下载格式规范），把试卷照片或文本丢给任意大模型换回可导入的 JSON。**应用自身不调用任何模型。**
- 可选的外部 JSON 管理入口：由部署者配置一个地址，未配置则该入口完全不存在。

### 4.2 学习数据管理

- 全量备份导出：把所有学习数据打包成一份带版本与时间戳的 JSON 下载。
- 恢复导入：两种模式——合并（只覆盖备份里有的项）/ 覆盖（先清空再写入），**覆盖必须二次确认**。
- 清空全部数据：不可撤销，必须双重确认（先激活、再确认）。
- 外观模式：浅色 / 深色 / 跟随系统三档，跟随系统时实时响应。

### 4.3 七个功能入口（+ 一个总览入口）

#### 首页 / 总览（home）
- 回答"今天该学什么、学到哪了"。
- 必须能呈现：题库总题数、已学过数、已掌握数、待复习数、今日到期数、**今日应学队列长度**、错题总数、最近 7 天趋势、本周活跃天数 vs 周目标天数。
- 可直达其余功能。

#### 学习（study）——背诵式自评流，跨会话记忆
- 状态机：配置 → 进行中 → 小结。
- 配置项：范围（今日到期 / 未掌握 / 全部 / 错题本 / 自定义序号区间+题型勾选）、排序策略（到期优先 / 顺序 / 随机）、每轮题数（预设档 + 自定义）。
- 每题流程：看题干 → 看答案 → 自评"记住了 / 还不会"→ 前进。
- 结果写：进度表；"还不会"同时进错题本。
- 进行中的每题位置写恢复点；退出=暂停，下次可"继续上次"。
- 小结呈现：对/错计数、本轮新增掌握数、本轮新增错题数、最高连对、用时。
- 当前题必须能看到**这道题的历史**（学过几次、是否已掌握、上次是否答错、当前连对数）。
- 题型勾选默认不含问答题。
- 支持键盘：看答案键、"记住了/还不会"各有两个键位（方向键与数字键）。

#### 练习（exercise）——自己作答，系统判分
- 与学习的**唯一区别**：多一个"提交答案"步骤，客观题由系统判，主观题揭示参考答案后自评。
- 每题流程：作答 → 提交 → （客观题自动判 / 主观题自评"算我答对了 / 还是答错了"）→ 前进。
- 结果写：进度表 + 错题本（答错时）。
- 恢复点、题型勾选（默认全含）、范围/排序/每轮题数同学习；默认策略随机、默认每轮"全部"。
- 配置处显示"错题本范围内可用题数"，用于发起错题重练。

#### 记忆闯关（practice）——会话内队列，一次即掌握
- 进入即把当前卷题目建成一个待攻克队列（可被题库声明关闭洗牌）。
- "记住了" → 该题永久移出本轮，进度前移；"没记住" → 埋到队尾第 5~7 张之后重来，同时进错题本。
- 必须能呈现：本轮剩余题数、已攻克数、完成度。
- **注意**：这是"一次即掌握"，与跨会话的"连对 5 次才掌握"是两套并存模型（见 §5、§11）。
- 换卷或数据变化即重置队列。队列本身不跨会话恢复。
- 答案文案（"记住了"/"没记住"的措辞）可被题库 JSON 覆盖。

#### 摸底速览（preview）——考前逐题过一遍
- 顺序浏览当前卷全部题，每道题都能单独看到答案。
- 一键把某题加入错题本（已存在则明确告知，不重复计）。
- **不写进度、不判分**：这是纯浏览动作，对记忆模型没有任何影响。
- 查看状态在换卷时清空。

#### 模拟考试（exam）——计时自测，交卷一次性判分
- 状态机：配置 → 进行中 → 成绩。
- 配置：范围/排序/题型/每轮题数（默认随机、默认 50 题、自定义档 100）。
- 过程中：**不反馈对错、不显示答案**；随时可改答；可回看任意题并修改；未作答/已作答必须可区分。
- 逐题作答快照持续写入恢复点：刷新、关页面、中途退出都不丢已答内容；退出前必须确认并明确告知"已答内容会保留"。
- 计时：从开始累计，跨退出延续。
- 交卷：若有未作答，必须先告知未作答题数并取得确认（当前用系统级确认，具体形态可换）。
- 交卷后**三分法**（这是本功能最核心的口径，必须清楚表达）：
  1. 客观题 → 立即判分，错者进错题本；
  2. 主观题且已作答 → 转入**待自评**，此刻不算错、不计分，在成绩页逐题对照参考答案评定后才计入；
  3. 未作答 → **不计分、不写进度、不进错题本**，单列供回卷。
- 正确率分母 = **已判分题数**（答对+答错），不含待自评与未作答。成绩页必须能说明这个口径，否则用户会误读分数。
- 成绩呈现：正确率、对/错数、未答数、用时、错题清单、待自评清单。

#### 分类考试（category）——按题型自测，实时判分
- 先选择题型（可全选/反选），从当前卷该题型题目里随机出题。
- 每题：作答 → 提交 → 客观题即时判；主观题揭示答案后自评。
- 答对：短暂展示正确反馈后自动前进（约 0.6 秒）；答错：**停在本题**直到用户看懂答案，并即时进错题本。
- 可回看上一题，回看时**保留当时的作答与判分结果**。
- 交卷前无"未作答"概念——空白提交一律判错。
- **不写跨会话进度**：这里答对答错都不影响"什么时候该复习这道题"，答错只进错题本（见 §5.5）。
- 结束呈现：对错数、正确率、用时、错题清单。
- 也可从错题本发起"重考错题"，走同一套流程，但**答对即刻移出错题本**（与错题本内部"连对 3 次才移出"是两条不同规则，见 §11）。

#### 错题本（wrongbook）——薄弱项清单
- 列出全部错题，可按**出错来源**分组查看；只列真实有题的来源。
- 每题必须能表达：题干与答案、你的答案、出错次数、连对次数、状态、首次出错时间、最近出错时间、来源。
- 操作：单条移除 / 按来源清空 / 发起"错题重练" / 发起"错题重考"。
- **重练**走记忆闯关式队列，但答对推进的是错题本状态机（见 §5.3），连对 3 次自动移出错题本并明确告知。
- 状态分布必须可查（新错 / 巩固中 / 模糊 / 已掌握）。
- 只有在这两个入口里答对才会让错题离开；**在其它入口答对不会移除错题**（见 §11）。

## 5. 记忆与调度语义（三套状态机 + 一条取题管线）

设计必须能分别表达这三套，它们是**互不相干**的：一次作答可能同时推进其中两个。

### 5.1 会话内队列（记忆闯关、错题重练）
- 记住一次 = 当场移出；没记住 = 埋到第 5~7 张之后重现。
- 只管"这轮还出不出现"，不产生跨会话含义。

### 5.2 跨会话进度（学习 / 练习 / 模拟考试 / 记忆闯关 / 错题重练会写；**分类考试与摸底速览不写**）
- 状态：`new` →（答对）`learning` → 连对 ≥3 `review` → 连对 ≥5 `mastered`。
- 下次复习间隔按连对次数阶梯：`0 → 1 → 3 → 7 → 14 → 30` 天（连对 5 次及以上固定 30 天）。
- 答对：次数与连对 +1，重排下次复习时间。
- 答错：连对归零、状态退回 learning、**下次复习时间=立即**、已掌握的题降级为 review。
- 手动干预：**能力已实现但没接到界面**——数据层可直接把某题标成"已掌握"（连对数抬到 5）或"已遗忘"（退回 learning 并立即待复习），当前用户做不到（见 §9）。
- 到期判定：非 mastered 且下次复习时间 ≤ 现在；从未记录过的题视为新题=到期。

### 5.3 错题本状态机
- 入库：新错即入，按 gid 全局去重；**重复入库会把状态打回 `new`、连对归零、出错次数 +1**。
- 状态：`new`（首次/最近答错）→ `learning`（错 ≥2 次且之后答对过 1 次）→ `weak`（连对 ≥2）→ `mastered`（连对 ≥3，**自动移出错题本**）。
- 在错题本内答错：连对归零、状态回 `new`、出错次数 +1。
- 注意 `learning` 只在答过一次对之后才可能出现；答错一律是 `new`。

### 5.4 取题管线（学习 / 练习 / 模拟考试共用唯一实现；分类考试走自己的"按题型筛+洗牌"）
`范围过滤 → 题型过滤 → 排序 → 每轮数量截断`

| 维度 | 可选值 |
|---|---|
| 范围 | 全部 / 今日到期 / 未掌握 / 错题本 / 自定义（序号区间 + 题型勾选） |
| 排序 | 到期优先 / 顺序 / 随机 |
| 每轮数量 | 预设档 + 自定义正整数 + "全部" |

- **硬不变式**：界面上预告的"将学 N 题"必须等于实际排队出来的题数。历史上两者长期不一致，重做时这条必须保持（这是功能正确性，不是视觉细节）。
- 每日任务生成优先级：**到期复习 > 未掌握 > 新题**（新题也算到期），已掌握跳过，最后截断到每日目标数。

### 5.5 写入矩阵（每个入口到底改了用户的哪些长期状态）

这是重设计最需要看清的一张表——**同样叫"考试"的两个入口，写的内容完全不同**。

| 入口 | 判分 | 写跨会话进度 | 写错题本 | 有恢复点 | 影响每日任务 |
|---|---|---|---|---|---|
| 学习 | 用户自评 | ✅ | ✅（还不会时） | ✅ | ✅ |
| 练习 | 客观题自动 / 主观题自评 | ✅ | ✅（答错时） | ✅ | ✅ |
| 模拟考试 | 交卷时自动 + 主观题自评 | ✅ | ✅（判错时） | ✅（含逐题答案） | ✅ |
| 记忆闯关 | 用户自评 | ✅ | ✅（没记住时） | ❌ | ✅ |
| 分类考试 | 客观题自动 / 主观题自评 | **❌ 不写** | ✅（答错时） | ❌ | **❌ 无影响** |
| 摸底速览 | 不判分 | **❌ 不写** | ✅（手动标记时） | ❌ | ❌ |
| 错题重练 | 用户自评 | ✅ | ✅ 状态机推进 / 连对 3 次移出 | ❌ | ✅ |
| 错题重考 | 走分类考试流程 | **❌ 不写** | 答对**立即移出** | ❌ | ❌ |

- 结论：**在分类考试里答对一万次，跨会话进度与今日任务都不动**；速览翻十遍也不动。若设计侧认为"刷过就该有记忆后果"，这是一处必须补的功能缺口，不是样式问题。

## 6. 必须能被表达出来的语义状态（清单）

这些是"事实"，不是组件要求。设计要保证**每一条都有不歧义的呈现方式**：

1. 题目当前所处状态：未作答 / 已作答 / 已判对 / 已判错 / 待自评 / 已自评对 / 已自评错。
2. 跨会话记忆状态四档：新 / 学习中 / 需复习 / 已掌握，以及**下次复习时间**。
3. "到期"是与上面四档**重叠的另一个维度**（一道"学习中"的到期题同时属于两者），不可相加。
4. 错题状态四档：新错 / 巩固中 / 模糊 / 已掌握（自动离开）。
5. 同一道题的"答对了"（当次）与"掌握了"（跨会话）——**两个数，两个名字**。
6. 进度位置：本轮第几题 / 本轮总题数。
7. 本轮内已产生的结果分布：对数、错数、新增掌握数、新增错题数、连对峰值。
8. 时间：本轮已用时长；考试的总用时。
9. 错题的"为什么在这里"：出错来源、出错次数、连对次数、首次与最近时间。
10. 存在未完成的会话可继续，并说明做到第几题 / 本轮共几题（当前界面即如此）。"什么时候留下的"数据层已记录，界面尚未呈现——要不要呈现由设计侧定。
11. 数据来源性质（远程 / 粘贴 / 文件 / 缓存 / 内置）与读取时间——用户需要知道自己在刷哪份数据。
12. 当前是哪一卷、题库共几题、这一轮会刷到几题。
13. 交卷/清空/覆盖导入这三类**不可逆动作前的确认**。
14. 空态必须区分成因：题库里没有这种题型 / 这道范围被筛空了 / 今天没有到期题 / 错题本已清空。
15. 错题离开的原因：连对 3 次自动移出 vs 重考答对立即移出 vs 用户手动删除。

## 8. 底线约束（技术与平台，不可谈）

- **必须能双击本地文件直接打开**：无构建步骤、无模块化加载、无 CDN、无外部字体/图片/脚本。新增任何第三方运行时依赖都不被允许。
- **完全离线可用**：断网、内网、U 盘场景是真实用例。
- **可选安装为独立窗口应用**（需走 http/https）；本地文件方式下该能力不存在属正常。
- 本地文件方式下浏览器禁止读同目录数据文件，因此"自动加载远程题库"只在服务器部署时生效——**必须保留手动导入三条路**（粘贴 / 选文件 / 拖入）。
- 远程拉取依赖对方服务器允许跨域；不允许时必须能改走手动导入且不卡死。
- 数据全部留在本机浏览器，不上传任何服务器。换设备只能靠导出/导入。
- 无障碍与平台下限（这些是门禁底线，不是风格）：触摸目标 ≥ 44×44pt、相邻目标间距 ≥ 8px；文字对比度按 WCAG AA 正文 4.5:1；所有评分/提交/跳转操作键盘可达且有可见焦点态；尊重 `prefers-reduced-motion`；任何常驻贴边、承载操作内容的区域必须避让系统安全区（`env(safe-area-inset-*)`）。
- 纯逻辑与界面分离：判分、取题、进度、统计、错题状态机都有唯一实现处且可独立跑单测——**新设计不得产生第二套判分或第二套取题口径**。

## 10. 已知口径矛盾（数据层事实，重设计时要一并解决）

1. **"错题总数"与"题库总题数"不同口径**：错题本是跨题库的全局数据，首页分母是当前卷。换卷或换库后，两个数不在同一坐标系里。
2. **`weak` 一词有两套含义**：首页的"待复习"= 进度侧 learning+review；错题本的"模糊"= 连对 2 次。代码里同名，界面上必须换成两个不歧义的名字。
3. **错题来源"考试"合并了两类考试**：分类考试与模拟考试写入的错题来源相同，无法区分"错在哪个场景"。当前对外标签叫"考试"。
4. **摸底速览加入的错题不带作答事实**：没有"你的答案"、没有对错，只表示"我标记了这题"。
5. **趋势里的"答错"是近似值**：系统不记录每次作答，只按"有错题记录且最近复习日在这天"估算当日错误数，**不等于真实当日错误数**。
6. **恢复点用题库标题做归属**：标题为空或改名会串/丢恢复点。
