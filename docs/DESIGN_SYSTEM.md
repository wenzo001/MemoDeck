## 0a. 工程落地记录（实现时发现的三处文档内矛盾，及采用的取舍）

这份文档整体可直接实现，但有三处内部数字互相冲突。工程侧按「硬门槛优先、偏好让路」处理，
并在此留痕，避免后续有人按文档另一处「改回来」：

1. **§5.3 的 768/1024 双栏宽度 vs §验收「平板 240px 作答栏为最窄约束」**  
   768 档：视口 768 − 页面留白 40 − 侧栏 200 − 分栏间距 24 − 题面栏 328 − 折痕安全边 24  
   = 作答栏只剩 **152px**，低于 240 的下限。1024 档同理只有 224px。  
   → 采用：作答栏 `min-width: 240px` 为硬约束，题面栏改为 `flex-shrink`（先退的是它）。  
   实测 768 → 240/240、1024 → 464/240、1440 → 480/440，无一处文案被裁。
2. **§7.3「需复习 = learning + review 聚合」vs §设计稿今日页四档 48/14/14/34 相加=110**  
   若「需复习」是聚合值，四档就会重复计数、相加超过总题数。  
   → 采用：四档互斥（需复习 = review 档），保证「相加＝总题数」这条用户能一眼验的算术成立；  
   聚合口径 `weak = learning + review` 仍保留在数据层供旧调用方使用。
3. **§设计稿今日页「错题四档 11/5/4/3 相加=23」vs §7.4.1「累计连对 3 次自动移出」**  
   已攻克的题已经离开错题本，不可能同时是 23 的组成部分。  
   → 采用：保留自动移出（§7.4.1 是明确决策），前三档是「当前还在本子里」的题，  
   「已攻克」改为**历史累计**（数据层新增移出留痕 history），并在界面口径条里写明它不计入总数。

**§4.5「图标全部居中」这条硬门槛的实测结果（3.0.0）**  
按本文 prescribed 的自检法（容器临时铺高对比底色，看字形是否偏离几何中心）在真 Chromium
上跑了 22 / 24 / 30 / 44 四档，四档各有主人：22 = `.md-opt-key`（单选圆点/多选方框）、
24 = `.md-judge-badge`（判错横幅徽标）、30 = `.md-resume-icon`（恢复提示卡）、
44 = `.theme-btn` / `.icon-btn` / `.md-resume-close`（图标按钮）。

第一版**没有通过**，且根因不在文档给的那两条规则上：`.icon` 为「图标 + 文字」的行
自带 `margin-right: .375em`，而 `justify-content: center` 抵不过单边外边距 ——
22 档实测字形中心偏 2.07px，恢复卡与退出按钮同样偏。规则 1「容器给底色、图标给字形」
与规则 2「flex 居中」都照做了，仍然错位，所以文档这条要补一句：**居中的方形容器必须把
图标自带的排距外边距关回 0**。落地时这张「零外边距名单」放在 `components.css` 的
`[icon-box]` 一条规则里，并由 `test/icons.test.js` 双向核对（新容器漏进名单 → 红；
名单里留着模板已删除的类名 → 红）。修完四档实测 dx=dy=0。

另外 §7.6 诚实声明的「所有断点均未在真实浏览器渲染」这一条，在 3.0.0 已由真 Chromium
在 320/360/430/560/768/1024/1440 七档实测补齐；色觉障碍模拟与读屏实测**仍未做**，状态不变。

## 1. 视觉主题

### 1.1 定位

**一句话**：一张暖色的纸，上面摆着��得清清楚楚的账。

产品要在两种感受之间取平衡——「不幼稚」和「不冷淡」。成人备考用户不需要哄，但也需要愿意每天打开。因此：

- **专业为底**：暖纸墨色体系（画布近白暖灰、正文墨黑）、克制的圆角与阴影、所有数字口径可追溯。
- **卡通为辅**：暖琥珀作为唯一强调色、圆角几何、进度与掌握状态的即时视觉反馈。卡通只出现在**反馈层**，不出现在**信息层**。

### 1.2 视觉谱系

|    | 主谱系                        | 辅助谱系                      |
| -- | -------------------------- | ------------------------- |
| 名称 | 暖纸墨色 Warm-Paper Ink        | 琥珀暖调 Amber Warm           |
| 承担 | 画布、表面、文字、边框、主操作、圆角、阴影      | 进度、到期、学习中、掌握脉冲、趋势图主色      |
| 禁止 | 不使用纯灰蓝企业色、不使用渐变背景、不使用大面积色块 | 不用于主按钮、不用于判对/判错、不与状态绿红蓝混用 |

**不应复制的内容**：不做满幅品牌色画布（暖橙铺满整屏会让 6 分钟碎片时间显得闹）、不做拟物卡片堆叠、不用插画占据题面区域（题面必须纯文本优先，插画会干扰长题干的阅读）。

### 1.3 一个关键取舍：主操作色为什么不用琥珀

第一版方案按「暖橙主色」铺开后被我推翻。原因是这个产品的**四个语义色已经把色相占满了**：

- 琥珀 → 到期 / 学习中
- 绿 → 判对 / 已掌握 / 已攻克
- 蓝 → 需复习 / 待自评
- 红 → 判错 / 新错

如果主按钮也用琥珀，「开始学习」会和「今日到期」在视觉上撞车，用户会本能地犹豫。灰（未作答/新题）留给状态第五档。

**结论**：主操作取墨色（浅色模式墨底白字，深色模式纸底墨字），琥珀退居为**唯一强调色**。这同时解决了「主操作不该和状态抢注意力」和「深色模式怎么做主按钮」两个问题。

## 3. 字体

### 3.1 字体族

```css
--md-font-ui: -apple-system, BlinkMacSystemFont, "PingFang SC",
              "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans SC", sans-serif;
--md-font-num: "Inter Tight", Inter, system-ui;  /* 指标数字，tabular-nums */
```

**仅系统字体栈，零 Web 字体**——这是离线硬约束。数字用 `Inter Tight` 是因为它在 `font-variant-numeric: tabular-nums` 下数字等宽，指标不跳动；中文正文用 `Noto Sans SC` 兜底以保证 Linux/内网机器字形一致。

页面声明 `lang="zh-CN"`，英文片段标 `lang="en"`。

### 3.2 字号阶

| 角色    | 移动端   | 行高   | 字距 | 承载内容          |
| ----- | ----- | ---- | -- | ------------- |
| 关键指标  | 52/56 | 1.08 | 0  | 今日题数、正确率      |
| 页面标题  | 24/32 | 1.33 | 0  | 空态标题          |
| 题干    | 18/29 | 1.61 | 0  | 可承载 120 字长题干  |
| 选项    | 15/24 | 1.6  | 0  | 可承载 40 字选项    |
| 正文/解析 | 14/25 | 1.79 | 0  | 可承载 300 字参考答案 |
| 标签按钮  | 13/18 | 1.38 | 0  | 芯片、次按钮        |
| 元信息   | 12/18 | 1.5  | 0  | 口径说明、计数       |

**字距恒为 0**，不使用负字距。中英文混排不机械加空格。

移动端输入框字号 ≥16px 防止 iOS 自动缩放。

### 3.3 内容压力下的取舍

- 长题干：自然换行，不截断（截断会让用户无法判断题目是否完整）。
- 长选项：换行，行高 1.6 保证可扫读。
- 容器挤压时**先丢元信息、再降间距、最后才考虑缩小字号**，且正文绝不低于 14px。
- 千题级列表：不做分页，虚拟滚动由工程侧实现；设计层保证行高稳定（错题条目固定最小 88px）。

### 4.2 六种题型的呈现契约

| 题型 | 标识 | 判分 | 题干 | 答案呈现 | 作答控件 |
|---|---|---|---|---|---|
| 填空 | `fill_blank` | 用户自评 | `____` 渲染为下划线占位块 | 逐空列出，序号显式 | **逐空输入框**（见下方决策） |
| 判断 | `true_false` | 系统 | 纯文本 | 「错误 / 正确」 | 两个大按钮高 88 |
| 单选 | `single_choice` | 系统 | 纯文本 + A–Z 键 | 键 + 文本 | 圆形单选点 22×22 |
| 多选 | `multi_choice` | 系统 | 纯文本 + A–Z 键 | 键 + 文本 | 方形勾选框 22×22 + 无部分给分提示 |
| 问答 | `essay` | 用户自评 | 纯文本 | 参考文本（≤300 字，不折叠） | 多行文本域 ≥16px + 字数 |
| 专项 | `special_fill_blank` | 用户自评 | 同填空 | 同填空 | **复用 FillBlank 组件**，序号色改蓝 |
| 未知 | 未注册 | 不判分 | 纯文本兜底 | 原始字段原样展示 | 不提供，仅浏览 |

**形状即语义**：单选用圆形点、多选用方形框、填空用带序号的输入框。开发者不得因为视觉统一而混用形状。

**专项题不另写实现**：答案形状与填空题完全一致，仅题型标签不同、序号色改为蓝色（普通填空用琥珀）。共用同一组件。

**未知题型走 DefaultRenderer**：题型注册表驱动，未注册标识显示题干 + 答案原始字段，不解析结构、不提供作答、不写进度。题型标签显示原始 `type` 字符串，便于用户反馈给部署者。

#### 填空题输入形态：设计决策

放弃「单输入框 + 手写竖线分隔」，改为**逐空输入**。理由：

1. `|` 分隔符**不参与任何判分**，纯靠用户手动约定，输错无从校验；
2. 逐空输入让每空独立可定位，序号显式，对照参考答案时更准；
3. 兼容做法：题库里的 `|` 仅在**导入时**拆分为逐空答案，界面层完全不出现分隔符。

判分仍为用户自评——没有逐空判分，也没有文本比对（不忽略大小写、无同义词、无空白差异）。

**凡带选项的题，选项文本与答案必须同屏可见**——背诵场景要「题干+选项+答案」一起读，不能只给答案字母。

### 4.3 共享判分结果组件（判断/单选/多选共用）

三种自动判分题型共用同一组件，**仅判分逻辑不同**。界面结构与数据写入完全一致。

| 状态 | 视觉 | 写进度表 | 写错题本 | 前进行为 |
|---|---|---|---|---|
| 答对 | 绿底 + 对勾徽标 | 次数+1、连对+1、重排下次复习 | ❌ | 自动前进（分类考试停留 0.6 秒） |
| 答错 | 红底 + 叉号徽标 | 连对归零、退回 learning、下次复习=立即；已掌握降级为 review | ✅（gid 全局去重，重复入本状态打回 new） | **停在本题**，不自动前进 |
| 待自评 | 蓝底 + 圆点徽标 | 此刻不写 | ❌ | 成绩页逐题评定后才计入 |

**判分逻辑（全局唯一口径，不得产生第二套实现）**：

```
判断：所选布尔与标准一致 → 对；未作答 → 错（不送分）
单选：所选字母与标准全等 → 对；未作答 → 错
多选：所选字母集合排序后全等 → 对；未作答 → 错
异常：答案形状不合约定时按空集处理，该题永远判错，但不崩溃
填空 / 问答 / 专项：无判分逻辑，一律用户自评
```

### 4.4 作答状态全表

7 种状态，每种都有形状 + 文字线索：

| 状态 | 视觉 |
|---|---|
| 未作答 | 白底 + 灰描边，无勾选标记 |
| 已作答  | 琥珀底面 + 实心勾          |
| 已判对  | 绿底面 + 实心对勾 + 「正确」   |
| 已判错  | 红底面 + 实心叉 + 「你选」    |
| 待自评  | 蓝底面 + 蓝点 + 「未计入正确率」 |
| 已自评对 | 绿底面 + 「算我答对」已选      |
| 已自评错 | 红底面 + 「还是答错」已选      |

### 4.5 图标构建规则（实现约定）

图标走查中发现的真实缺陷：**图标不居中、被容器的底色盖住**。根因是把"底色形状"和"图标字形"当成了两个并列元素排列，而不是叠放。

**实现约定**：

1. **容器负责底色与圆角，图标只负责字形。** 勾选框的琥珀底 + 7px 圆角由容器（CSS `background` + `border-radius`）提供；对勾是唯一的子元素。
2. **图标一律用 flex 居中，禁止手写偏移量。** `display:flex; align-items:center; justify-content:center`。不要用 `padding` 或绝对定位去"挪"图标——改尺寸时必然再次错位。
3. **一个图标 = 一个内联 SVG。** 不要把底色和字形拆成两个元素；也不要让图标的 `fill` 与容器底色相同（同色叠加会让字形不可见）。
4. **形状即语义，不可因视觉统一而互换**：多选用**方形**勾选框、单选用**圆形**单选点、填空用**带序号**输入框、判断用**两个大按钮**。
5. **描边型图标（返回、暂停、关闭）的圆底由容器给，箭头/竖条是子元素**。暂停图标只需两根竖条，不要额外画外框——外框会与竖条重叠，读起来像渲染错误。
6. **居中的方形容器里，图标自带的外边距必须关回 0。** 若图标基类为了「图标 + 文字」的横排而带 `margin-right`，`justify-content:center` 也救不回来 —— 单边外边距会把字形从几何中心推走（实测 22×22 的勾选框被推 4.125px，字形中心偏 2.07px）。排间距交给容器的 `gap`，不要交给字形。

自检方法：把图标容器的背景临时设成高对比色，若字形偏离几何中心，即为错位。此检查在四种尺寸（22 / 24 / 30 / 44）下都要做。**四档都要真正量到**：24 档的徽标只在交卷后出现，30 档的恢复图标只在存在恢复点时出现，22 档的对勾只在选中或判分后出现——不把这些状态构造出来，检查就是在扫空气。

## 5. 布局

### 5.1 信息架构（8 入口 → 4 导航）

这是本次重设计最大的结构决策。8 个入口两两相似，用户无法判断该用哪个。

| 新导航     | 容纳的原入口                  | 收敛理由                                        |
| ------- | ----------------------- | ------------------------------------------- |
| **今日**  | 总览                      | 保留，改为「今天该学什么」单一焦点                           |
| **练习**  | 学习 + 记忆闯关 + 分类考试        | 三者都是「逐题推进」，差异只是**判分方式**与**是否写长期进度**，属配置而非入口 |
| **错题本** | 错题本                     | 保留，但重练/重考降为错题本内的两种发起方式                      |
| **题库**  | 数据接入 + 手动加题 + 导出备份 + 外观 | 全部收纳为一个二级页                                  |
| （练习内模式） | 模拟考试                    | 独立「考试」模式：交卷统一判分是唯一无第二例的机制                   |
| （练习内模式） | 摸底速览                    | 降级为「浏览模式」：不判分、不写进度，只读                       |

**练习页的模式切换**（分段控件，一次性设置）：

| 模式     | 判分    | 写长期进度 | 有恢复点 | 答错行为    |
| ------ | ----- | ----- | ---- | ------- |
| 背诵（自评） | 用户自评  | ✅     | ✅    | 停留      |
| 答题（判分） | 客观题自动 | ✅     | ✅    | 停留并展示答案 |
| 按题型自测  | 客观题自动 | ✅     | ✅    | 停留      |
| 模拟考试   | 交卷统一  | ✅     | ✅    | 不立即反馈   |
| 浏览速览   | 不判分   | ❌     | ❌    | 不适用     |

**这样用户只需回答一个问题：「这轮我要做什么？」** 而不是「这 8 个入口有什么区别」。

### 5.2 主流程

1. **冷启动（首次打开 / 零数据 / 零网络）**  
   首屏不是空态插画，而是**内置兜底题库直接可练**（13 题）。顶部一条来源标识条：「内置示例题库 · 13 题 · 想换题库点这里」。用户第一次打开就能完成一次完整刷题，不需要先配置任何东西。
2. **进题**：粘贴 / 选文件 / 拖入 → 自动识别三种格式 → 顶部来源标识切换为「本地文件 · 10/9 12:03」。
3. **每日一刷**：今日 → 「今天该学 12 题」→ 开始学习 → 逐题自评 → 小结。
4. **考前模拟**：练习 → 模拟考试 → 计时交卷 → 成绩三分法 → 逐题自评待定项。
5. **攻薄弱项**：错题本 → 攻薄弱项 → 答对 3 次自动移出并明确告知。

### 5.3 断点与导航形态

| 断点               | 导航形态        | 内容布局                                           |
| ---------------- | ----------- | ---------------------------------------------- |
| **320–359**      | 底部导航 **3 栏** | 单列；水平内边距 **16**（比常规少 4）；错题四档由 4 列降 **2×2**；隐藏「预计用时」等次要元信息 |
| **360–429**      | 底部导航 4 栏   | 同上，内边距回到 18                                 |
| **430–559（折叠态）** | 底部导航 4 栏   | 标准单列，内边距 20；顶部加形态切换提示条；底部固定操作区不可省             |
| **560–767**      | **左侧栏 200** | 单列内容，题面与选项上下排列                                 |
| **768–1023**     | **左侧栏 200** | **双栏**：题面栏 328 固定 / 作答栏自适应；题面栏内额外承载「本题历史」卡片    |
| **1024–1439**    | **左侧栏 232** | 双栏：题面栏 480 / 作答栏自适应；选项区限宽，字段宽度铺满但不超 680        |
| **1440+**        | **左侧栏 232** | 双栏同 1024；**内容区不再加宽**，题面栏维持 480，避免行长超 960       |

**导航形态切换点定在 560px**，理由：低于此宽度底部导航横跨屏幕会让两端超出拇指可达范围；高于此宽度手握姿势下底部导航命中率显著下降。

**320 窄屏的导航取舍（本设计唯一牺牲一级导航直达性的地方）**：4 栏横排后每栏仅 72px，低于 44pt 触控目标的舒适区（需 ≥88px）。因此收为「今日 / 练习 / 更多」3 栏，**错题本与题库收进「更多」**。错题本是高频入口，但在 320px 下无解，只能二级可达。360px 以上全部恢复 4 栏直达。

### 5.4 各端专属能力（不是等比放大）

| 端       | 独有设计                                                                  |
| ------- | --------------------------------------------------------------------- |
| 平板 / 桌面 | 侧栏导航项带**数字角标**（今日待学数、错题数），移动端因空间不足不带                                  |
| 平板 / 桌面 | 题面栏展&#x793A;**「这道题的历史」**&#x5361;片（学过次数、上次结果、当前连对、错题记录）——移动端放不下，宽屏才有价值 |
| 桌面      | 每个选项右侧显示**键位徽标**（A/B/C/D）；hover 态显示「点击或按 C」；侧栏底部常驻**快捷键面板**           |
| 桌面      | 操作区为「上一题 + 提交答案」双按钮，移动端只有单一主按钮                                        |
| 折叠屏展开   | 双栏，但题面栏右缘留 24px 安全边避让折痕；**折痕区不承载任何可交互元素**                             |
| 折叠屏     | 顶部显示当前形态（展开 · 双栏 / 折叠 · 单栏）；折叠后顶部保留一条「折叠后仍可继续作答，进度自动保留」               |

**宽度原则**：宽屏不是把移动端拉宽，而是**把移动端放不下的信息补上**（历史、角标、键位）。字段宽度永远不超过 680px，超出即损害扫读。

### 5.4 间距与圆角

- 间距：4 / 8 / 12 / 16 / 20 / 24 / 32（8pt 基线）
- 圆角：8（芯片）/ 12（选项、说明）/ 16（卡片、恢复提示）/ 20（主卡、弹层）/ 27（按钮）/ 999（药丸）
- 层级：**内 < 相关项 < 分组 < 区块**。区块间 24–28，组内 12–14，元素内 8–12。
- 卡片只用于真正独立的重复对象（今日任务、成绩、错题条目、待自评题）。不嵌套卡片。

### 5.5 安全区与输入

- 顶部：`env(safe-area-inset-top)`，状态栏占位不叠加。
- 底部固定操作区 `padding-bottom: 20 + env(safe-area-inset-bottom)`；PWA 独立窗口无地址栏时同样保留。
- 输入框 `font-size: 16px` 防止 iOS 缩放；`inputmode` 按题型选（填空用 text，问答用文本域）。
- 常驻底部内容避开 home indicator。

## 7. 注意事项

### 7.1 禁止项

| 禁止              | 原因                  |
| --------------- | ------------------- |
| 满幅品牌色画布         | 6 分钟碎片时间场景下过于刺激     |
| 主按钮用琥珀/绿/红/蓝    | 与四个语义状态撞车           |
| 渐变背景、玻璃拟态       | 与「可信、专业」冲突；且离线性能差   |
| 卡片套卡片           | 层级噪声                |
| emoji 做图标       | 跨平台渲染不一致            |
| 纯色块传达状态         | 色觉障碍用户不可用           |
| 「答对」与「已掌握」共用一个词 | 两个不同的数，用户会误读        |
| 省略口径说明          | 用户无法解释数字来源，产品核心价值崩塌 |

### 7.2 必须表达的口径（缺一不可）

1. 正确率分母 = 已判分题数（不含待自评、未作答）
2. 多选无部分给分
3. 「到期」与记忆四档重叠，不可相加
4. 错题本跨全部题库统计，与当前卷题数不同口径
5. 趋势里的「答错」是估算值
6. 每题答错/答对后的双状态写入（错题本 + 记忆进度）

### 7.3 命名消歧（本次重设计的核心）

代码里两个不同概念都叫 `weak`，界面必须用不同名字：

| 归属      | 四档命名                     | 说明                          |
| ------- | ------------------------ | --------------------------- |
| 跨会话记忆进度 | 新题 / 学习中 / **需复习** / 已掌握 | 「需复习」= learning + review 聚合 |
| 错题本     | 新错 / 巩固中 / **模糊** / 已攻克  | 连对 2 次为模糊，连对 3 次移出为已攻克      |
| 会话内队列   | 本轮攻克                     | 闯关「一次即掌握」改称此名，明确不产生跨会话含义    |

**「当次答对」与「跨会话已掌握」是两个数、两个名字、不可相加。**

### 7.4 已决策事项（原阻塞项，现已确认）

| # | 事项              | 决策                  | 落地要求                                                                                                                |
| - | --------------- | ------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 1 | **错题离开规则三条不一致** | ✅ **已采纳建议：收敛为单一规则** | 「任何入口答对即计连对，累计 3 次自动移出 + 明确告知原因」。**需改数据层**：原「错题重考答对 1 次即移出」的短路逻辑要移除；「其它入口答对不移出」要改为计次。移出时必须告知原因（连对 3 次自动移出 / 用户手动删除） |
| 2 | **功能开关只覆盖两个入口** | ✅ **已确认：保留旧键名做映射**  | 题库 JSON 的旧开关键名**不改名、不删除**，映射到新模式：关闭「记忆闯关」→ 隐藏练习内的「闯关队列」模式；关闭「摸底速览」→ 隐藏练习内的「浏览速览」模式。答案文案覆盖能力同样保留                     |

**兼容性要求**：旧题库 JSON 不含任何新字段即可正常工作；新设计不引入第二个开关契约。部署者对旧键名的认知继续有效。

### 折叠屏专项规则

1. **折痕区禁放可交互元素**：题面、选项、提交按钮均不跨折痕；题面栏右缘留 ≥24px 安全边。
2. **形态切换不丢状态**：折叠/展开时作答内容、计时、当前位置全部保留。恢复点持续写入，不依赖屏幕尺寸。
3. **当前形态可见**：顶部常驻「展开 · 双栏」/「折叠 · 单栏」标识，避免用户误以为页面变了。
4. **首次折叠给提示**：折叠瞬间顶部滑入一条「折叠后仍可继续作答，进度自动保留」，3 秒后自动消失。
5. **触控目标不因形态变小**：折叠态勾选框仍 22×22，不低于 20px。

**`prefers-reduced-motion` 降级**：取消全部位移与脉冲，仅保留 100ms 透明度变化；进度条直接跳变；答对自动前进的 0.6s 停留保留（它是节奏控制不是装饰动效）。形态切换提示条改为直接出现，不滑入。
